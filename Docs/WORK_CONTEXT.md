- 최근 성능 구조: `character_repository`는 캐릭터 원본 payload에 대해 기존 15초 메모리 TTL cache를 먼저 보고, miss 시 `cache/character-response-cache.sqlite`의 60초 SQLite cache를 확인한다. SQLite hit은 메모리 cache를 다시 채우며, API 성공 payload만 디스크에 저장한다.
- 최근 성능 구조: 서약 탭 표시용 `oathUpgrades` 조립 결과는 기존 `character-response-cache.sqlite`에 `resource="oathUpgrades"`로 저장한다. 기존 raw `oath`/`mist_assimilation` 캐시와 item detail memory cache를 재사용하며 새 SQLite 파일은 만들지 않는다.
- 최근 캐시 구조: `server/repositories/resolved_price_repository.py`는 정상 가격을 600초 fresh TTL로 사용한다. 정상 응답이지만 매물이 없으면 마지막 성공 가격을 유지하거나 무매물 음수 결과를 600초 보관한 뒤 재조회하고, API 오류/타임아웃은 60초 후 재시도한다. 만료된 성공값은 즉시 삭제하지 않고 최대 4096개 LRU 범위에서 보존하며 raw auction rows가 아닌 해석 완료 가격 결과만 저장한다. generic itemId/동일 이름의 마지막 성공 경매장 가격은 `Docs/.price_cache/auction_last_known.json`에도 최대 10000개를 영속 저장해 서버 재시작 후 복구한다.
- 최근 경매장 가격 정책: itemId의 fresh/마지막 가격 → 동일 이름으로 이미 확인된 거래품 가격 → 캐시가 없으면 동일 이름 경매장 API 1회 조회 순으로 해석한다. 이벤트·교환불가 itemId라도 동일 이름 거래품이 있으면 그 itemId/이름을 `priceItemId`/`priceItemName`으로 보존한다. 현재 매물이 없더라도 한 번 성공한 가격은 `isLastKnownPrice=true`로 유지한다. 서버 재시작 시 영속 가격의 마지막 성공 시각이 10분 이내면 남은 fresh TTL을 그대로 복구하고, 10분을 넘겼을 때만 현재 경매장을 즉시 재확인한다.
- 최근 재료 가격 정책: 정상 조회된 마지막 최저가는 이후 매물 없음 또는 API 오류 응답으로 덮어쓰지 않고 비용 계산에 유지한다. 현재 조회가 실패한 항목이 있으면 재료 가격 payload는 60초 TTL로 계속 갱신한다.
- resolved price cache 적용 domain: generic `auction_item`/`auction_exact_name`, `avatar_emblem`, `platinum_emblem`, `black_fang_scroll`, `switching_fragment`, `switching_title`, `aura`. 마부·칭호·오라·크리쳐 가격 카탈로그도 refresh 시 이전 성공 가격을 병합해 현재 무매물 때문에 후보가 사라지지 않게 한다.

- 최근 UI 정책: 캐릭터 로드아웃 패널은 `장비`/`서약`/`아바타` 탭을 제공한다. 기본은 장비 탭이며, 서약 탭은 기존 `oathUpgrades.crystals` 배열과 setName/setPoint를 읽어 표시 전용 보드로 렌더링한다. 아바타 탭은 실제 payload 연결 전까지 캐릭터 프리뷰와 10개 아바타 슬롯을 `클론 레어` 상태로 읽기 전용 표시한다.
- 최근 버프강화 정책: `Docs/switching_avatar_db.json`은 클래스 단위 스위칭 상하의 레어 아바타 후보 DB다. 현재 경매장 매물 또는 최근 거래 이력이 확인된 itemId만 남긴다. 딜러는 버프강화 상의/하의 슬롯이 레어가 아닐 때 아바타+플티/플티 완성품 가격을 비교하며, 버프강화 아바타 슬롯이 비어 있으면 현재 착용 아바타를 fallback으로 현재 contribution에 반영한다. 버퍼는 `bufferBaseline.buffSkillName` 기준으로 상의/하의 아바타 매물을 플티와 주스탯 엠블렘 x2까지 채우는 총 비용으로 환산하되, 이미 레어 스위칭 상/하의 아바타가 있으면 합본 추천을 만들지 않고 기존 개별 플티/엠블렘 추천 흐름을 유지한다. 합본 추천의 버프 스킬 레벨 증가는 칭호처럼 해당 아바타 슬롯의 contribution 전후 차이로 계산한다. 장비 상의/아바타 상의가 모두 `slotId=JACKET`을 쓰므로 mixed switching rows에서는 `slotName`에 `아바타`가 있는 row만 아바타 교체 대상으로 삼는다. 경매장 row의 상의 옵션은 `avatar.ability`를 `optionAbility`로 정규화하고 nested emblems는 top-level로 올려 중복 카운트를 막는다. raw 버프강화 슬롯이 없어 현재 착용 아바타가 fallback으로 들어간 경우 `bufferStatGain`은 fallback/후보의 엠블렘 스탯 차이와 self-stat skill delta 차이만 반영하고, item detail 직접 스탯 차이는 제외한다.
- 최근 마부 정책: 업그레이드 가능한 마법부여 카드/보주는 효과를 max upgrade 기준으로 쓰므로 가격도 `upgrade == upgradeMax`인 풀업 경매장 row만 인정한다. 풀업 매물이 없으면 노업 가격으로 효율을 계산하지 않고 기존 가격 없음 흐름을 탄다. 같은 부위/효과 방향에서 가성비 또는 준종결 마부가 상위 tier보다 실제 효율이 낮으면 추천 row 후처리에서 제외한다.
- 최근 마부 교정: `acquisition.label`이 있는 재료 마법부여는 경매장 `unlisted` 상태와 무관하게 골드 0의 유효한 시뮬레이터 적용 대상으로 처리한다. 일반 가격 미확인 마부의 적용 차단은 유지한다.
- 최근 강화/증폭 정책: 무기 강화/증폭 추천은 현재 공격력 기준이 독립공격력이고 무기 재련이 있으면 115레벨 재련 독공 표를 반영한다. 독공 실효 증가는 `max(강화/증폭 독공, 현재 재련 독공)` 전후 차이만 인정하고, 12강 이상 최종 데미지 보너스는 기존처럼 별도 반영한다. 독공 비증폭 무기는 안전강화와 무기 증폭 후보를 비교해 효율 좋은 1개만 남긴다.
- 최근 버프강화 정책: 딜러 스위칭 칭호/크리쳐 contribution 계산은 `buffSkillName`과 `equivalentSwitchingPlatinumSkills`를 함께 인정한다. 레벨 범위형 효과는 target skill별 requiredLevel을 독립 합산하고, 추천 실효 상승량은 스위칭 레벨 cap 7을 적용한다.
- 최근 버프강화 UI: `buffLoadout` 슬롯에는 기존 판별 helper로 계산한 선택적 `buffContribution` 요약만 추가하며, 프론트 툴팁은 원본 enchant/emblems/detail 없이 해당 표시값을 그대로 사용한다.
- 최근 서약 정책: `서약 결정 초월`/`서약 정가` 추천은 각각 `oathTranscendRecommendations`/`oathCraftRecommendations` 별도 필드와 `oathTranscend`/`oathCraft` sourceType으로 기존 `oathUpgrades`/서약 조율과 분리한다. 장비 세트포인트 2550 미만 또는 미확인 캐릭터는 초월/정가 추천을 생성하지 않는다. target 서약 결정은 exact item search/detail 검증 후 생성하고, 딜러/버퍼별 유효 옵션과 세트포인트 교체 효과를 반영하며, 에픽/태초 추천은 rarity별 최상위 1개와 일반 에픽 8칸/태초 3칸 cap을 반영한다. 고유 current는 허용하되 target 고유는 제외하고, target family는 중앙 서약 표시의 원본인 `setInfo.setOptionName`의 family 접두사로 정한다. `창조의 안개 결정 - 반지`는 딜러 current 최종 데미지 19%로 계산한다.
- 서약 초월·정가 슬롯은 현재 결정의 약한 등급부터 `유니크 → 레전더리 → 고유 에픽 → 일반 에픽` 순으로 교체하며, 같은 등급 안에서는 딜러는 최종 데미지, 버퍼는 버프력 상승량을 기준으로 세트포인트 순위와 함께 선택한다. family가 없는 고유 에픽은 타 family가 아닌 중립 결정으로 이 순서를 따른다.
- 혼합 서약 결정은 원본 `oath.setInfo.setOptionName`의 ` : ` 앞 family를 중앙 표시와 추천의 단일 주 family 권위로 사용한다. 에픽/태초 target은 모두 주 family로 통일하고 명시적인 타 family 결정을 기존 등급·역할별 비교보다 먼저 교체하며, rarity별 통합 카드 identity는 유지하고 `targetFamilyName`으로 active selection과 snapshot 수량을 검증한다. 타 family 결정의 raw 슬롯 세트포인트는 복원용으로 보존하되 현재 주 세트 계산 기여는 0으로 처리한다.
- 서약의 가호 버프력은 API `oath.blessing.status`를 기준으로 계산하며, 유니크 구간은 서약포인트 25당 `+80`, 그 외 기존 등급 구간 계수는 `oath_tune_stage_db.json` 값을 따른다.
- 서약 초월·정가 통합 카드는 수량·방식을 바꿀 때마다 `baseOathUpgrades`에서 태초 전체 계획을 먼저 배치하고 남은 슬롯에 에픽 전체 계획을 배치한 뒤 최종 결정 배열을 한 번에 적용한다. 적용 카드 snapshot도 태초는 base→태초, 에픽은 태초 적용 상태→최종 상태 순서로 평가하며, 활성 서약 조율은 최종 배열 위에 다시 계산한다.
- 최근 유일 제작 정책: `우아한 기품의 향수` target body의 버프력은 본체 12,930과 정밀도 100% 4,650을 합친 17,580으로 한 번만 정규화한다. 장비 조율 단계 버프력 변화는 기존처럼 별도 delta로 유지한다.

- 최근 유일 조율 교정: target body가 `tuneUpgradeable=false`이면 본체 교체 시 `tuneLevel/tuneRemaining`을 0으로 초기화하고, 해제 시 원래 장비의 조율 상태를 복원한다. 활성 장비 조율 선택은 본체 교체 전에 무효화하며 이후 추천은 현재 시뮬레이터 장비의 세트포인트를 기준으로 다시 계산한다. 유일 자격 최소 세트포인트도 서버 payload의 권위 값을 현재 시뮬레이터 장비 합계에 재적용해, 기준 미만이면 미적용 유일 후보를 제외하고 적용 snapshot은 해제용으로 유지한다.
- 최근 필수 조율 교정: 유일 장비 본체를 가상 장착한 뒤 기존 조율 배분으로 장착 후 세트포인트 2550 도달 가능 여부를 판정한다. 도달 가능한 후보는 부족분을 해제 불가 `1/N` 첫 variant로 자동 적용하고, 필수 조율 활성 중에는 별도 일반 장비 조율 카드를 만들지 않는다. 일반·필수 조율 사이를 전환할 때 기존 선택 variant를 유지하며, 본체 변경 시 현재 유일 구성 기준으로 계획을 다시 만든다.
- 최근 흑아 교정: 흑아 recommendation presenter는 `sourceType=blackFang`을 원본 payload부터 제공한다. 공통 장비 본체 초기화가 현재 장비 `bodyEffects`를 놓치지 않아 시뮬레이터 최종 데미지가 목표값 추가가 아니라 기존 본체 대비 교체 배율로 계산된다. 심장 연동 `1.03`은 추천 카드의 실제 딜 평가용 `plagueHeartActualDamageMultiplier`로만 적용하고 추천 row의 공통 `skillDamageMultiplier`나 장비 본체에는 합치지 않는다. 따라서 심장 장착 상태에서 흑아를 적용하면 실제 딜 카드에는 연동 +3%가 포함되지만 공식 장비점수는 흑아 본체 변화만 반영한다.
