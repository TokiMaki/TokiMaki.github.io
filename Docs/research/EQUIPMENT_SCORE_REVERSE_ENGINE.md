# 장비점수 역산기 설계 메모

이 문서는 장비점수 증분 계산의 현행 구현과 역산 연구 결과를 함께 정리한 기준 문서다.

공식 장비점수의 절대값을 처음부터 재현하는 완성 공식은 아직 확보하지 못했다. 현재 제품은 공홈에서 확인한 현재 장비점수를 기준값으로 사용하고, 시뮬레이터가 계산한 변경 전후비만 적용한다.

기존 `equipment_score_reverse_notes.md`는 초기 회귀/탐색 메모가 섞여 있으므로, 구현 시에는 이 문서를 우선한다.

## 목표

목표는 공식 장비점수를 복사해서 표시하는 것이 아니라, 특정 투자/교체가 공식 장비점수를 얼마나 올리는지 계산하는 것이다.

핵심 구조:

```text
변경 후 장비점수 ~= 현재 공식 장비점수 * 데미지 전후비 * 기타 고정점 보정
```

데미지 전후비는 공식 장비점수 계산의 파티 플레이 기준 스탯으로 계산한다.

## 현행 시뮬레이터 계산 계약

딜러 시뮬레이터가 화면에 표시하는 예상 장비점수는 다음과 같다.

```text
예상 장비점수 = round(현재 공홈 장비점수 * 누적 장비점수 배율)
```

- 현재 공홈 장비점수는 `equipmentScore` 기준값이다.
- 누적 장비점수 배율은 `getSimulatorCumulativeDamageMultiplier(simulator, "equipmentScore")`가 계산한다.
- 최종 표시는 `getSimulatedEquipmentScore()`에서 `Math.round()`한다. 이 문서의 과거 `floor` 표기는 현행 코드와 다르다.
- 실제 딜 상승량은 같은 시뮬레이터 상태를 `actual` 모드로 계산한다. 장비점수 전용 인정 규칙이 있으므로 실제 딜 배율과 장비점수 배율은 다를 수 있다.
- 버퍼점수 표시는 이 계약과 다르다. 공홈 버프점수에 내부 `calculateBufferScore()`의 기준 대비 점수 차이를 더한다.

따라서 현재 구현은 다음을 하지 않는다.

```text
캐릭터의 모든 항목을 0점부터 합산해 절대 장비점수를 생성
장비 세트/무기 실측표를 직접 조회해 현재 장비점수를 재구성
실측값만으로 공홈 장비점수를 완전히 대체
```

### 누적 장비점수 배율 구성

일반 스탯 계열은 현재와 시뮬레이션 상태의 합계 차이를 만든 뒤 한 번 계산한다.

```text
주스탯
공격력
속성 강화
공격력 증가
공격력 증폭
```

최종 데미지는 위 합계에서 제거한 뒤, 서로 독립된 교체 축의 전후비를 각각 곱한다.

```text
마법부여 슬롯
오라
크리쳐
크리쳐 아티팩트
장비 본체 슬롯
강화/증폭 단계
장비 조율
서약 결정
서약 조율/가호
유일 장비 조건부 효과
칭호
실착 플래티넘
버프강화
```

같은 축의 교체는 다음 비율을 사용한다.

```text
(1 + 목표 최종데미지 / 100)
/
(1 + 현재 최종데미지 / 100)
```

서로 다른 축은 이 전후비를 곱한다. 예를 들어 세트 최종 데미지와 무기 최종 데미지를 단순히 더하지 않는다.

### 현행 구현과 연구값 구분

| 항목 | 현행 시뮬레이터 적용 | 상태 |
|---|---|---|
| 공홈 장비점수 기준값에 누적 배율 적용 | 적용 | 제품 계약 |
| 파티 주스탯/공격력/속강/공격력 증가/증폭 전후비 | 적용 | 일부 계수는 실측 기반 추정 포함 |
| 최종 데미지 축별 교체 전후비 | 적용 | 현행 코드 |
| 장비점수 전용 아바타 일반 엠블렘 인정 스탯 | 적용 | 실측 및 정책값 |
| 실착 플래티넘 인정 계수 `1.20 + 인정 레벨 * 0.02` | 적용 | 현행 정책값 |
| 버프강화 장비점수 인정 계수 | 적용 | 현행 정책값 |
| 그림자 장비 세트 단계 실측표 | 직접 적용하지 않음 | 절대값 역산용 참조 |
| 태초/검은 질병 무기 실측표 | 직접 적용하지 않음 | 절대값 역산용 참조 |
| 서약 0~749점 가호 최종 데미지 | 미적용 | 실측됐으나 현행 누락 |
| 0점부터 시작하는 절대 장비점수 공식 | 미구현 | 추가 역산 필요 |

### 현재 baseline fallback

필수 딜러 baseline이 0 또는 누락된 경우 현행 프론트는 일부 항목에 다음 기본값을 사용한다.

```text
주스탯 6,500
직업 기본 스탯 800
속성 강화 330
공격력 4,000
```

`elementDamage`는 유한한 숫자 `0`이면 실제 값으로 취급한다. 이 fallback은 계산 중단을 피하기 위한 현행 동작이지 공식 장비점수 규칙으로 검증된 값이 아니다. API 미제공과 실제 0을 구분하는 데이터 계약은 별도 과제다.

## 공식 기준

공식 가이드 기준 장비점수는 아래 상태를 기준으로 계산된다.

```text
버프 강화 옵션 포함
지역 버프 포함
임의 사양 버퍼의 버프를 받은 파티 플레이 상태
```

버퍼 기준값:

```text
30Lv 버프 스탯: 168,350
30Lv 버프 공격력: 31,215
100Lv 버프 스탯: 297,900
```

현재 검증 결과상, 주스탯 변화 계산에는 30Lv 버프 스탯과 100Lv 버프 스탯을 모두 더해야 한다.

## 기본 스탯 테이블

직업별 기본 스탯은 `Docs/jobBaseStat.json`을 사용한다.

예시:

```text
眞 로그: 힘 815
眞 듀얼리스트: 힘 779
```

지역버프 계산에는 캐릭터의 주스탯에 해당하는 기본 스탯을 사용한다.

## 지역버프 공식

현재 검증된 지역버프 공식:

```text
지역버프 주스탯 = floor(3.08 * (마을 주스탯 - 직업 기본 주스탯) + 2886)
```

장비 변경으로 마을 주스탯이 바뀌면 지역버프도 변경 후 마을 주스탯 기준으로 다시 계산한다.
지역버프는 최종 파티 주스탯에 더하기 전에 소수점을 버린다.

마키로그 검증:

```text
마을 힘: 6,679
기본 힘: 815

floor(3.08 * (6679 - 815) + 2886)
= 20,947

실측 지역버프: 20,948
```

주의:

```text
마키로그 실측 지역버프 20,948과 위 floor 계산 20,947은 1 차이가 있다.
지역버프 자체 표시값은 반올림/올림 가능성이 있으나,
장비점수 전후비 계산에서는 floor 처리 후 최종 장비점수도 floor 처리했을 때 실측과 맞는 케이스가 있다.
```

마키듀얼 최신 API 검증:

```text
마을 힘: 6,553
기본 힘: 779

floor(3.08 * (6553 - 779) + 2886)
= 20,669

지역버프 힘 ~= 20,670
```

## 파티 기준 주스탯

장비점수용 파티 주스탯:

```text
파티 주스탯 =
  마을 주스탯
+ 30Lv 버프 스탯 168,350
+ 100Lv 버프 스탯 297,900
+ 지역버프 주스탯
```

주스탯 배율:

```text
주스탯 배율 = 1 + 파티 주스탯 / 250
```

전후비:

```text
주스탯 전후비 =
(1 + 변경후 파티 주스탯 / 250)
/
(1 + 변경전 파티 주스탯 / 250)
```

## 파티 기준 공격력

공식 버퍼 기준의 30Lv 버프 공격력:

```text
30Lv 버프 공격력: 31,215
```

API `status`의 마을 물리/마법/독립 공격력은 직업 패시브나 무기 마스터리로 증폭된 값일 수 있으므로 장비점수 baseline에 직접 사용하지 않는다.

레벨 115의 기본 공격력 잠재 능력 `95`에 실제 평면 공격력 기여를 각각 더해 증폭 전 공격력을 재구성한다.

```text
증폭 전 공격력 =
  기본 공격력 잠재 능력 95
+ 장비/칭호 본체의 해당 공격력
+ 장비 마법부여의 해당 공격력
+ 무기·귀걸이 강화 공격력
+ 독립 공격 직업의 무기 재련 공격력
+ 실착 오라 본체 공격력
+ 실착 크리쳐·아티팩트 공격력
```

공격력 종류는 `Docs/job_attack_type_db.json`의 `jobId + jobGrowId`별 `attackSources`를 따른다. 독립 공격 직업의 무기는 강화와 재련 공격력 중 큰 값을 사용한다.

마키로그 검증:

```text
기본 공격력 잠재 능력: 95
본체 공격력: 1,832
  무기 1,757 + 오라 50 + 크리쳐 아티팩트 25
마법부여 공격력: 290
강화 공격력: 1,211
  13강 무기 1,126 + 11강 귀걸이 85

95 + 1,832 + 290 + 1,211 = 3,428
```

마키로그 API 마을 물리 공격력 `5,042`에는 로그의 무기 마스터리 증폭이 포함돼 있으므로 사용하지 않는다. 같은 세팅의 증폭 전 물리 공격력은 위 합산 결과인 `3,428`이다.

현재 파티 공격력 추정:

```text
파티 공격력 = 증폭 전 공격력 + 31,215
```

## 속성 강화 / 속성 배율

속성 강화는 API 마을 `status` 값만 쓰면 안 된다.

115제 장비/서약/세트 등으로 던전에서 적용되는 속강이 API 마을 `status`에 빠지는 경우가 있다.

마키로그:

```text
API 암속강: 306
던전/시뮬 암속강: 436
누락 속강: +130
```

마키남슾:

```text
API 속강: 311
장비 누락 속강: +130
계산 기준 속강: 441
```

속성 배율은 인게임 검증상 아래 식을 사용한다.

```text
속성 배율 = 1.05 + 속성강화 * 0.0045
```

참고:

```text
속강 222 증가 시 피해율은 99.9% 증가
=> 속강 1당 0.45%
```

전후비:

```text
속성 전후비 =
(1.05 + 변경후 속강 * 0.0045)
/
(1.05 + 변경전 속강 * 0.0045)
```

## 공격력 증가

공격력 증가는 총합 전후비로 계산한다.

```text
공격력 증가 전후비 =
(1 + 변경후 공격력증가총합 / 100)
/
(1 + 변경전 공격력증가총합 / 100)
```

마키로그 마법석 교체 검증:

```text
기존 마법석: 공격력 증가 3189, 최종 데미지 35.3%
교체 마법석: 공격력 증가 2100, 최종 데미지 30%

총 공격력 증가 차이: -1089
기존 총 공격력 증가: 71104.5

공격력 증가 전후비:
(1 + (71104.5 - 1089) / 100)
/
(1 + 71104.5 / 100)
= 0.984706

실제 장비점수:
150,173 -> 129,910

공격력 증가 하락과 최종 데미지 하락을 곱하면 실제 하락과 거의 일치.
```

## 최종 데미지 증가

OpenAPI `status`의 `최종 데미지 증가`는 정보창 집계값이지만, 현행 시뮬레이터는 이 총합 하나에 모든 변경값을 더하지 않는다.

일반 효과 합계에서는 `finalDamage`를 제외하고, 마법부여/오라/크리쳐/장비 본체/강화·증폭/조율/서약 등 각 교체 축의 정규화된 현재·목표 효과를 전후비로 계산한다. 같은 축의 현재 효과는 빼고 목표 효과를 넣으며, 서로 다른 축의 전후비는 곱한다.

단일 옵션 교체 예시:

```text
최종 데미지 1% -> 2%

전후비 = 1.02 / 1.01
```

마키로그 목걸이 마부 검증:

```text
현재 점수: 150,173
전후비: 1.02 / 1.01 = 1.00990099
예상 증가: +1,486.86
```

## 장비 세트 단계 실측 참조값

아래 값은 그림자 세트 기준 인게임 `최종 데미지 증가` 표기와
`Docs/OATH_VALUE_REVERSE_TABLE.xlsx`의 단계별 `공격력 증가` 입력값이다.
현재는 역산을 위한 참조값이며, 별도 검증 없이 계산기에 자동 적용하지 않는다.

- 그림자 최종 데미지는 사용자 인게임 표본으로 확인한 값이다.
- 공격력 증가는 현재 역산 엑셀에 기록된 입력값이다. 모든 행을 인게임에서 독립적으로 재검증한 값으로 간주하지 않는다.
- 현행 시뮬레이터는 아래 표를 단계 lookup으로 직접 사용하지 않는다. 장비 본체의 정규화 효과와 별도 장비 조율 변화를 기준 상태 대비로 계산한다.

## 무기 최종 데미지 실측 참조값

아래 값은 사용자 인게임 표본에서 확인한 `최종 데미지 증가` 수치다. 역산 참조표 자체는 현행 시뮬레이터가 직접 조회하지 않는다.

| 무기 상태 | 최종 데미지 증가(%) |
|---|---:|
| 태초 무기 1조율 | 398.2 |
| 태초 무기 2조율 | 420.6 |
| 태초 무기 3조율 | 444 |
| 검은 질병 무기 | 500 |

현행 최종 데미지 교체식에 이 값이 정규화 효과로 들어오면 `500%`는 `1 + 500 / 100 = 6` 배율로 해석한다. 현재값과 목표값이 모두 있으면 절대 배율을 그대로 곱하지 않고 다음 전후비를 적용한다.

```text
(1 + 목표 무기 최종데미지 / 100)
/
(1 + 현재 무기 최종데미지 / 100)
```

따라서 표의 `500`을 `5`배로 직접 곱하거나, 다른 세트 최종 데미지와 합산하는 방식은 현행 구현과 다르다.

## 스킬 레벨 옵션 환산

칭호의 `1~95Lv 모든 스킬 Lv +1`은 장비점수 계산에서 최종 데미지 증가 8% 상당으로 환산한다.

마키헌터 `프로스트의 전설` 검증:

```text
칭호 장착 장비점수: 96,755
칭호 제거 장비점수: 77,246

전체 전후비:
96,755 / 77,246
= 1.2525567667
```

칭호의 계산 가능한 옵션:

```text
힘 +100
칭호 마부 힘 +25
모든 속성 강화 +10
칭호 마부 수속성 강화 +6
공격력 증폭 +20%
1~95Lv 모든 스킬 Lv +1
```

Neople item detail API에서는 같은 칭호의 `itemBuff.reinforceSkill`에 `1~95Lv +1`이 있고, `itemStatus`에는 `최종 데미지 증가 8%`가 함께 내려온다.

따라서 장비점수 계산에서는 아래처럼 처리한다.

```text
1~95Lv 모든 스킬 Lv +1
= 장비점수상 최종 데미지 증가 8%
```

마키헌터 기준 `힘 +125`, `수속강 +16`, `공격력 증폭 +20%`, `스킬Lv +1 환산 최종 데미지 +8%`를 적용하면:

```text
floor(77,246 * 계산 전후비)
= 96,755
```

### 플래티넘 칭호

플래티넘 칭호의 `1~95Lv 모든 스킬 Lv +1`은 장비점수 계산에서 최종 데미지 증가 9.6% 상당으로 환산한다.

마키로그 `프로스트의 전설 플래티넘[35Lv]` 검증:

```text
칭호 장착 장비점수: 156,400
칭호 제거 장비점수: 123,060

전체 전후비:
156,400 / 123,060
= 1.2709247522
```

Neople item detail API:

```text
itemBuff.reinforceSkill:
  1~95Lv 모든 스킬 Lv +1

itemStatus:
  최종 데미지 증가 9.6%
```

칭호의 계산 가능한 옵션:

```text
힘 +100
칭호 마부 힘 +25
모든 속성 강화 +10
칭호 마부 암속성 강화 +6
공격력 증폭 +20%
1~95Lv 모든 스킬 Lv +1
```

장비점수 계산에서는 아래처럼 처리한다.

```text
플래티넘 칭호 1~95Lv 모든 스킬 Lv +1
= 장비점수상 최종 데미지 증가 9.6%
```

마키로그 기준 `힘 +125`, `암속강 +16`, `공격력 증폭 +20%`, `스킬Lv +1 환산 최종 데미지 +9.6%`를 적용하면:

```text
floor(123,060 * 계산 전후비)
= 156,400
```

일반 칭호 대비 플래티넘 추가분:

```text
1.096 / 1.08
= 1.0148148148

일반 칭호 대비 약 +1.48%
```

### 크리쳐 레벨 태그

크리쳐의 레벨 태그 옵션은 칭호처럼 `itemBuff.reinforceSkill`로 내려오지 않고, Neople item detail API의 `itemStatus`에 최종 데미지 증가 환산값으로 바로 내려온다.

마키로그 `운명을 담는 여신[35Lv]`:

```text

  힘 +150
  모든 속성 강화 +40
  공격력 증폭 +40%
  버프력 증폭 +10%
  최종 데미지 증가 +1.5%

itemBuff:
  null
```

마키헌터 일반 크리쳐 `운명을 담는 재단사`:

```text
itemStatus:
  힘 +150
  모든 속성 강화 +40
  공격력 증폭 +40%
  버프력 증폭 +10%

itemBuff:
  null
```

따라서 현재 검증 규칙:

```text
크리쳐 [35Lv] 옵션
= 장비점수상 최종 데미지 증가 1.5%
```

### 크리쳐 스킬 기여 역산값

크리쳐 레벨 태그에는 실제 특정 액티브 스킬 공격력 증가와 장비점수용 인정값이 함께 존재하므로 둘을 구분한다.

현행 제품 처리:

```text
실제 딜용 액티브 스킬 증가 fallback:
  [30Lv] = 해당 액티브 스킬 공격력 +15%
  그 외 레벨 태그 = 해당 액티브 스킬 공격력 +10%

장비점수용 API itemStatus:
  [35Lv] 크리쳐 = 최종 데미지 증가 +1.5%
```

대화 중 아무 효과가 없는 크리쳐로 교체해 확인한 전체 장비점수 표본은 다음과 같다.

```text
마키로그: 349,578 -> 247,097, 전체 비율 1.4147399604
마키듀얼: 268,170 -> 192,156, 전체 비율 1.3955848373
```

위 전체 비율에서 크리쳐 본체의 주스탯, 속성 강화, 공격력 증폭 등 확인 가능한 효과를 제외한 스킬 인정 잔여분은 약 `1.0159`, 즉 약 `+1.59%`로 두고 역산을 진행하기로 했다.

```text
크리쳐 스킬 장비점수 역산 근사 배율 = 1.0159
```

다만 이 값은 공식 일반식으로 확정된 값이 아니며 현행 시뮬레이터에도 별도 계수로 적용하지 않는다. 현재 제품은 API가 제공하는 장비점수용 `최종 데미지 +1.5%`와 실제 스킬 컨텍스트 계산을 사용한다. `1.59%`는 절대 장비점수 역산 연구에서 비교할 참조값이다.

## 현행 장비점수 전용 정책값

아래 항목은 절대 장비점수 역산으로 새로 도출하는 값이 아니라, 현재 시뮬레이터가 실제 딜 계산과 장비점수 표시를 분리하기 위해 사용하는 정책값이다.

### 실착 플래티넘 인정 계수

```text
인정 계수 = 1.20 + 인정 레벨 * 0.02
플티 교체 장비점수 배율 = 목표 인정 계수 / 현재 인정 계수
```

인정 레벨에는 현재 시뮬레이션 상태의 실착 칭호 인정 레벨, 상의 아바타 선택 옵션, 상의/하의 실착 플래티넘 기여를 사용한다. 실제 딜은 계산 가능한 스킬 배율을 별도로 사용하므로 장비점수 변화와 다를 수 있다.

### 버프강화 인정 계수

```text
유효 레벨 = 현재 스위칭 스킬 레벨 + 시뮬레이터 레벨 변화
장비점수 계수 = 100 - (20 - 유효 레벨) * 2 + 짙은 편린 개수 * 0.25
```

장비점수 모드에서는 목표 계수/현재 계수를 적용한다. 실제 딜 모드에서는 버프강화 스킬의 현재 계수와 레벨당 계수, 적용 비율을 사용한다.

### 다크나이트 차원일치

다크나이트처럼 `statPostMultiplier`가 있는 경우 현행 주스탯 계산은 이미 증폭된 마을 스탯을 그대로 다시 증폭하지 않는다.

```text
증폭 전 스탯 = 마을 스탯 / 현재 statPostMultiplier
변경 후 증폭 전 스탯 = 증폭 전 스탯 + 변경 스탯
최종 유효 스탯 = 파티 기준 스탯 계산 결과 * statPostMultiplier
```

즉 새로 더한 힘/지능에도 현재 차원일치 레벨 계수가 적용된다.

### 장비 조율 기억 효과

현행 장비 조율 장비점수 배율은 2,550점을 기준으로 그 이후 70점마다 최종 데미지 2%가 증가하는 정책을 사용한다. 첫 2% 단계는 2,620점이다.

```text
기억 단계 = max(0, floor((총 장비 세트포인트 - 2550) / 70))
기억 배율 = 1 + 기억 단계 * 0.02
조율 변화 배율 = 목표 기억 배율 / 현재 기억 배율
```

이 값은 앞의 그림자 세트 단계 최종 데미지 표와 별도 축이다.

### 유일 장비 특수 규칙

유일 장비는 정규화된 장비 본체 효과를 일반 장비 교체 경로에 넣되, 다음 특수 효과는 현재 DB의 권위값으로 먼저 합성한다.

```text
우아한 기품의 향수:
  (1.489 * 1.131 * 지진파 환산 배율 - 1) * 100
  = 최종 데미지 70.67376612%

영롱한 날씨의 큐브:
  (1.502 * 1.10 * 1.0159935^5 - 1) * 100
  = 최종 데미지 약 78.86166335%

만병을 잉태한 역병의 심장 본체:
  (1.502 * 1.10 - 1) * 100
  = 최종 데미지 65.22%
```

역병의 심장 흑아 연동은 실제 딜과 장비점수 정책이 다르다.

```text
실제 딜: 흑아 개수만큼 1.03을 곱함, 최대 3개
장비점수: 흑아 개수와 무관한 고정 배율 1.092552
버퍼: 흑아 1개당 버프력 +75, 최대 3개
```

이 값들은 현재 제품 정책이다. 공식 절대 장비점수 공식으로 확정된 일반 규칙으로 확대 적용하지 않는다.

## 쿨타임 감소

쿨감은 일반 DPS식 그대로 쓰면 장비점수와 맞지 않는다.

### 마법석 15% 표본과 일반 DPS 환산

일반 DPS 기준 쿨타임 감소 환산식은 다음과 같다.

```text
쿨감 DPS 배율 = 1 / (1 - 쿨타임 감소율)

쿨감 15%:
1 / (1 - 0.15)
= 1.1764705882
```

이 값은 `scripts/calculate_equipment_damage_index.py`의 탐색용 `cooldown_damage_ratio()`에도 사용한다. 그러나 공식 장비점수의 쿨감 인정식으로 검증된 값은 아니다.

대화 중 서약 결정을 모두 제거한 표본에서 다음 값을 확인했다.

```text
기준 장비점수: 3,191
11증 귀걸이 제거: 1,850
쿨감 15% 마법석 제거: 1,803
```

마법석 제거는 쿨감 외에도 장비 본체, 마법부여, 공격력 증가, 최종 데미지 등이 함께 빠지므로 `3,191 -> 1,803`만으로 쿨감 15%의 장비점수 인정 배율을 독립 확정할 수 없다. `1.1764705882`는 역산 비교용 일반 DPS 배율로만 보존한다.

현행 시뮬레이터의 `estimateDamageMultiplier()`에는 일반 `cooldownReduction` 항목이 없다. 따라서 마법석의 쿨감 15%를 위 일반 DPS식으로 직접 장비점수에 곱하지 않는다. 정규화된 다른 효과나 별도 정책 계수만 현재 예상 장비점수에 반영된다.

### 서약의 가호 쿨감 환산

서약의 가호는 일반 쿨감 환산식을 사용하지 않고, 유니크 이상 구간에서 장비점수용 최종 데미지 2%를 5회 곱하는 고정 정책을 사용한다.

```text
서약 가호 쿨감 환산 배율
= 1.02^5
= 1.1040808032
```

즉 서약 가호의 쿨타임 감소 18.5%를 다음처럼 계산하지 않는다.

```text
사용하지 않는 식:
1 / (1 - 0.185)
= 1.2269938650
```

현행 적용 범위:

```text
레어 가호: 쿨감 환산 배율 없음
유니크/레전더리/에픽/태초 가호: 1.1040808032를 상태 배율에 한 번 적용
```

서약 단계나 가호 구간을 교체할 때는 목표 전체 서약 상태 배율/현재 전체 서약 상태 배율로 계산하므로, 양쪽 모두 유니크 이상이면 같은 고정 쿨감 환산 배율은 상쇄된다.

검증 케이스:

```text
마키여긒
창조의 안개 결정 - 반지:
  최종 데미지 8%
  스킬 쿨타임 감소 20%

정화 : 선명한 광휘 결정:
  최종 데미지 20%

실제 장비점수:
51,239 -> 51,670
증가량 +431
```

`쿨감 20%`를 장비점수상 `최종 데미지 11%` 상당으로 보면:

```text
기존 환산 = 1.19
교체 환산 = 1.20

전후비 = 1.20 / 1.19 = 1.00840336
예상 증가 = +430.58
실제 증가 = +431
```

현재 임시 규칙:

```text
쿨감 20% ~= 장비점수상 최종 데미지 11%
```

주의:

```text
이 규칙은 검증 케이스 1개 기반이다.
쿨감 10/15/20/30 등 추가 표본으로 별도 곡선을 만들어야 한다.
```

## 아바타 / 엠블렘

아바타 엠블렘은 장비점수 계산과 실제 데미지 계산을 분리한다.

장비점수 계산에서는 노란빛/녹색빛 엠블렘 슬롯에 실제 주스탯 엠블렘이 박혀 있지 않아도, 해당 슬롯에 가능한 자기 주스탯 엠블렘이 박힌 것처럼 평가되는 것으로 본다.

현재 규칙:

```text
찬란한 노란빛/녹색빛 엠블렘: 개당 주스탯 +15
화려한 노란빛/녹색빛 엠블렘: 개당 주스탯 +10
```

주의:

```text
이 규칙은 장비점수 계산 전용이다.
실제 데미지 계산에서는 실제로 주스탯 엠블렘이 박혀 있지 않으면 주스탯 증가로 계산하지 않는다.
```

검증 케이스:

```text
마키로그
두 부위 제거 후 힘 -20 상태: 156,336
추가로 얼굴/목가슴 쪽 비교 후: 156,297
차이: -39
```

해석:

```text
얼굴/목가슴에 실제 공격속도 엠블렘이 박혀 있어도,
장비점수 계산은 해당 슬롯에 가능한 힘 엠블렘이 박힌 것으로 계산하는 듯하다.
```

현재 파티 스탯 공식으로 힘 -30을 계산:

```text
예상 하락 ~= -38.73
실측 하락 = -39
```

임시 규칙:

```text
얼굴/목가슴 공격속도 엠블렘 2개는 장비점수상 힘 엠블렘 2개, 즉 힘 30 상당으로 평가된다.
```

향후 구현 시 엠블렘은 `equipmentScoreVirtualStat`과 `realDamageStat`을 분리해서 계산한다.


### 레어아바타 상의/하의 장비점수 환산

레어아바타 상의/하의는 실제 옵션에 주스탯이 보이지 않아도, 장비점수 계산에서는 부위별 주스탯 +30이 포함된 것으로 보는 쪽이 표본 간 일관성이 높다.

검증 표본:

```text
마키듀얼
하의 제거: 139,422 -> 137,173
상의 제거: 139,422 -> 134,992

마키로그
하의 제거: 166,642 -> 163,955
상의 제거: 166,642 -> 161,348
```

주스탯 +30을 장비점수용 파티 스탯 전후비로 제거한 순수 상승률:

```text
하의 레어아바타: 약 +1.6140%
상의 레어아바타: 약 +3.2558%

두 표본 간 차이:
하의: 약 0.0008%p
상의: 약 0.0007%p
```

임시 규칙:

```text
레어아바타 하의 = 장비점수상 주스탯 +30 + 순수 데미지 약 1.614%
레어아바타 상의 = 장비점수상 주스탯 +30 + 순수 데미지 약 3.256%
```

## 구현 순서 제안

1. `jobBaseStat.json`을 로드한다.
2. API `status`에서 마을 주스탯, 속강, 공격력 증가, 공격력 증폭, 최종 데미지 증가, 쿨감 값을 읽는다. 공격력은 마을 표기값 대신 기본 95와 실착 아이템의 평면 공격력 기여를 합산한다.
3. 장비/세트/서약에서 API 마을 `status`에 누락된 던전 적용 속강을 더한다.
4. 지역버프를 계산한다.
5. 파티 주스탯/공격력을 만든다.
6. 변경 전후 옵션을 데미지 전후비로 바꾼다.
7. 현재 공홈 장비점수에 장비점수 모드 전후비를 곱한 뒤 최종 장비점수는 `Math.round()` 처리한다.
8. 쿨감/아바타/엠블렘/세트 고정점은 별도 검증표를 기반으로 추가한다.

## 서약의 가호 포인트 보정

서약의 가호 환산값은 `Docs/OATH_VALUE_REVERSE_TABLE.xlsx`의 등급별 시작값을 기준으로 계산한다.

### 750점 미만 실측과 현행 누락

대화 중 인게임 표본에서 서약 세트포인트가 655점인 상태에도 서약의 가호 최종 데미지가 적용되는 것을 확인했다. 현재까지 확인한 0~749점 규칙은 다음과 같다.

```text
0~749점 가호 최종데미지 = floor(현재 서약포인트 / 25) * 0.5%
```

750점에서는 위 값을 계속 누적한 `15%`가 아니라 레어 가호 시작값 `17%`로 전환된다.

```text
0~749점: 25점당 최종 데미지 +0.5%
750점: 레어 가호 시작값 최종 데미지 17%
```

750점 미만의 버프력과 명성 규칙은 아직 확인하지 못했다. 최종 데미지 규칙만 확정값으로 기록하며 나머지를 임의로 추정하지 않는다.

현행 코드에는 이 실측이 반영되지 않았다.

- `Docs/oath_tune_stage_db.json`의 `stageRows`와 `blessingRows`가 모두 750점부터 시작한다.
- 서버 `get_oath_tune_state()`와 프론트 `getOathTuneState()`는 stage 또는 blessing이 없으면 `null`을 반환한다.
- 프론트 `getOathTuneDamageMultiplier()`는 어느 한 상태라도 `null`이면 변화 배율 `1`을 반환한다.

따라서 현재 0~749점 구간의 서약 획득/교체 시뮬레이션은 확인된 가호 최종 데미지 변화를 누락할 수 있다. 이 문서는 차이를 기록만 하며 코드는 변경하지 않는다.

### 750점 이상 현행 계산

같은 등급 구간 안에서 서약포인트가 25 올라갈 때마다 현재 `blessingRows`의 등급별 값을 더한다.

| 가호 구간 | 25점당 최종 데미지 | 25점당 버프력 |
|---|---:|---:|
| 레어 | +0.5% | +70 |
| 유니크 | +0.5% | +80 |
| 레전더리 | +0.5% | +70 |
| 에픽 | +0.5% | +70 |
| 태초 | +1% | +120 |

명성은 역산 엑셀의 연구 항목에는 존재하지만 현행 장비점수/버프점수 시뮬레이터 상태 계산에는 사용하지 않는다.

계산식:

```text
구간 내 단계 수 = floor((현재 서약포인트 - 해당 등급 구간 시작 포인트) / 25)

최종데미지증가 = 등급 시작 최종데미지증가 + 구간 내 단계 수 * 해당 행 finalDamagePerStep
버프력 = 등급 시작 버프력 + 구간 내 단계 수 * 해당 행 buffPowerPerStep
```

구간이 바뀌면 이전 구간 보정은 누적하지 않고 새 등급 시작값에서 다시 계산한다.

딜러의 현행 서약 상태 배율은 다음 세 축을 곱한다.

```text
(1 + 서약 단계 최종데미지 / 100)
* (1 + 가호 최종데미지 / 100)
* 쿨타임 환산 배율
```

`cooldownEquivalent: true`인 유니크 이상 구간은 현재 고정 배율 `1.1040808032`를 추가로 적용한다. 시뮬레이터 변화량은 목표 상태 배율/현재 상태 배율이다.

각 서약 결정 본체의 `effects.finalDamage`는 결정별로 `1 + finalDamage / 100`을 곱하며, 서약 단계/가호 배율과 별도로 계산한다.

### 장비 세트/서약 세트 일치 보정

장비 세트와 서약의 주 세트가 같으면 최종 배율 `1.03`을 별도로 적용한다.

```text
장비 세트와 서약 세트 일치: 1.03
불일치: 1

일치 상태 변화 배율
= 목표 일치 배율 / 현재 일치 배율
```

따라서 불일치에서 일치로 바뀌면 `1.03`, 일치에서 불일치로 바뀌면 `1 / 1.03`, 양쪽 상태가 같으면 `1`이다. 이 보정은 서약 단계 최종데미지, 가호 최종데미지, 가호 쿨감 환산, 서약 결정 본체 효과와 중복하지 않는 별도 곱연산 축으로 취급한다.

공홈 장비점수를 기준값으로 사용하는 현재 구조에서는 검색 시점의 일치 보정이 기준 점수에 이미 포함돼 있다. 다만 현행 프론트 시뮬레이터의 `getOathTuneState()`, `getOathTuneDamageMultiplier()`, `getOathCrystalFinalDamageChangeMultiplier()`에는 장비 세트명과 서약 세트명을 비교하는 로직이 없다. 따라서 시뮬레이션으로 일치 여부 자체가 달라지는 경우의 `1.03` 전후비는 현재 명시적으로 재계산되지 않는다. 역산 엔진에서는 현재/목표의 canonical 세트 family를 비교해 위 전후비를 별도로 반영해야 한다.

예:

```text
레전더리 시작 최종데미지 39
현재 서약포인트 1700
=> 최종데미지 41

2100점이 다음 구간 시작점이면
=> 최종데미지 50, 버프력 8210, 명성 4105를 그대로 사용
```

## 미확정 항목

- 공격력 쪽도 100Lv 버프에 해당하는 별도 공격력 보정이 있는지 확인 필요.
- 지역버프가 주스탯 외 공격력에도 별도 적용되는지 확인 필요.
- 쿨감 환산 곡선은 추가 표본 필요.
- 노란빛/녹색빛 엠블렘은 장비점수상 찬란한 +15, 화려한 +10 주스탯으로 계산하는 규칙을 우선 적용하되, 다른 등급/다른 슬롯은 추가 검증 필요.
- 그림자 장비 세트와 무기 최종 데미지는 참조표를 확보했지만, 이를 포함한 0점 기준 절대 장비점수 공식은 아직 역산하지 못했다.
- 750점 미만 서약의 가호 버프력/명성 규칙은 미확정이다. 최종 데미지 실측만 현재 문서에 기록했다.
